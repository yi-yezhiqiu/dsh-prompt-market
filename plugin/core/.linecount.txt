### 1.1 单元体与核心文件的关系（**t17 订正：此前表述说过头了**）

⚠️ **订正说明**：本文件 t3 版曾写「每个单元体 = 对应核心文件的**逐字节原文**」。
**实测证明该表述过头**：单元体是**精简重写版**，不是逐字节原文。准确的描述是：

- **说明头被替换**：核心文件的 `plugin/core/<name>.js` 头注释，在 `browser.js` 里换成了更短的
  `unit: <name>` 单元说明头 ⇒ 单元体行数普遍**少于**核心文件。
- **个别写法更紧凑**：例如 `storage` 单元的缓存写入循环与 `buildExport` 的 `text.nowIso()`
  （语义等价、非逐字）；`api` 单元的注释亦有精简。
- 因此「browser.js ↔ 核心文件**逐行 diff**」**必然误报**，不得用作判据。
- 另注：`constants.js` 在 t3 之后有新变更（t13 改默认 `writeField`、t17 修正被阻断域名注释、
  t23 拆分 `MIT-plexpt` 许可条目），而 `browser.js` 的内联副本**已由 t23 同步**
  （`MIT-plexpt` 在 `constants.js` 与 `browser.js` 中同时存在，见 `docs/VERIFY-03-装配前复核.md` §3）。
  行号不再互指（本文件不再写「`browser.js:NNNN`」这类易失效引用）——**判据见 1.2，不靠行号对照**。

### 1.2 权威一致性判据（**唯一，保留并强化**）

> **一致性 = `plugin/client.js` 的 `PM-CORE-INLINE` 区段 ↔ `plugin/core/browser.js` 的单元区段，
> 逐行一致（忽略行首缩进与空行）。**

- `plugin/core/build-client-bundle.js --check` 实现的正是该判据（先取区段→再取单元区段→逐行归一化比较）；
- `plugin/ui/check-ui.ps1` 的 **A13** 同样按「区段对区段」比较；
- **不得**改用「`client.js` 或 `browser.js` 与 `plugin/core/*.js` 逐行比对」——那会因为上述
  精简重写（以及 t17 的注释漂移）而误报失败；
- **同样不得**改用「`client.js` 整文件 ↔ `browser.js` 整文件」比较：前者是装配产物（含壳层与 UI
  内联区），两者长度本就无关；**只比对区段内内容**。
- 判据的**输入两侧都是被冻结/受保护的**：`browser.js`（文件头注释修正后为 **4894 行**，**单元区段内容未变**）
  与已绑定指纹的 `client.js`（**6796 行 / 267728 字符 / 294237 字节 / sha256 `7CA1D1A6…`**，
  文件头注释修正后实测 sha256 **未变**）⇒ **本次刷新不会使该判据失效**。

`browser.js` 的 9 个单元体（→ `PM-CORE-INLINE` 区）与 8 个 UI 单元（→ `PM-UI-INLINE` 区）内联而成。

- **不得**手工同步 `client.js`；**不得**把它与 `browser.js` 做「整文件行数」比较

## 3. 安装包边界

`plugin/package.json` 的 `files` 白名单只有四项：`index.js`、`client.js`、`cordis.patch.yml`、`README.md`。
`plugin/core/**` 不在白名单内 —— 浏览器侧使用数据层的唯一方式是**内联进 `client.js`**，
因此本目录是「源码 + 可读参考」，不进安装包，也天然满足 t-integrate 验收④「交付目录无缓存与调试残留」。
